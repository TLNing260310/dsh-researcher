### Module dependencies
- `command.js` → argument.js (`Argument`, `humanReadableArgName`), error.js, help.js (`Help`, `stripColor`), option.js (`Option`, `DualOptions`), suggestSimilar.js
- `option.js` / `argument.js` → error.js; `help.js` → argument.js; `index.js` → all five
- **No cycles, no runtime third-party code** — a deliberately flat, acyclic dependency graph (C0-2).

### The parse pipeline (critical path)
1. **`_prepareUserArgs`** (command.js:1001-1065) — argv convention detection: node / electron (via `process.defaultApp` / `process.versions.electron`) / user / eval (`-e`, `-p`, `--eval`, `--print` in `execArgv`); derives program name from script filename.
2. **`parseOptions`** (command.js:1748-1895) — the heart. A single-pass tokenizer that splits argv into `operands` and `unknown`, handling: `--` literal; long options; `--foo=bar`; combined short groups (`-abc`); required/optional/boolean/negated/variadic options; negative-number disambiguation (`negativeNumberArg`, with the documented exception when a digit is itself a registered short flag); and two special modes — `enablePositionalOptions` (stop option processing at a subcommand name) and `passThroughOptions` (stop at first command-argument). Side effect: emits `option:<name>` events that assign values.
3. **Value resolution order** — CLI events → `_parseOptionsEnv` (env, only if current source is undefined/default/config/env) → `_parseOptionsImplied` (`.implies()` dual-option-aware) (command.js:1550-1553, 1966-2025).
4. **`_parseCommand`** (command.js:1550-1641) — dispatch: known subcommand → `_dispatchSubcommand`; help command → `_dispatchHelpCommand`; default command → `_dispatchSubcommand(default)`. Otherwise: help-if-requested, mandatory/conflict checks, unknown-option check, `_processArguments` (defaults, variadic collection, custom parseArg), then `preAction` hooks → action handler → legacy `command:<name>` parent event → `postAction` hooks, promise-chained via `_chainOrCall` (sync until first async).
5. **Errors** — `error()` → `outputError` → optional help-after-error → `_exit()` → `exitOverride` callback or `process.exit(exitCode)` (command.js:533-539, 1940-1958). `InvalidArgumentError` from user parseArg functions is caught in `_callParseArg` and converted to a formatted `error()` (command.js:599-609).

### Second dispatch path: executable subcommands
`.command('start', 'desc')` marks `_executableHandler` — at dispatch, Commander spawns `<program>-<sub>` (or `executableFile`/`executableDir`), searching `.js/.ts/.tsx/.mjs/.cjs` variants, launching via `node` for source files (required on Windows, line 1278-1288), forwarding SIGUSR1/2/SIGTERM/SIGINT/SIGHUP, incrementing `--inspect*` ports to avoid conflicts, and exiting with the child's code (command.js:1202-1346, 2705-2746). Legacy script-name-prefix lookup retained.

## 4. Design Decisions (and their rationale)

1. **Zero runtime dependencies** (CONTRIBUTING.md:40-43, with links to "package tsunami" arguments). Rationale: supply-chain safety, install size (packagephobia badge in README), simplicity. Consequence: hand-rolled edit distance (suggestSimilar.js), color detection (command.js:2752-2774), and wrapping — all small, tested, and dependency-free. **This is a hard constraint on any change: a dependency-adding PR "is much less likely to be accepted."**
2. **CJS core + ESM wrapper** (package.json:44-61; esm.mjs:1-16). One implementation, dual entry points, no dual-package hazard (ESM imports the CJS).
3. **EventEmitter as internal bus** (command.js:13). Option values, help text, legacy events all flow through events. This is simultaneously an architectural backbone and a compat surface (`option:<name>`, `optionEnv:<name>`, `command:<name>`, `command:*`, `--help`, `beforeHelp`/`afterHelp`/`beforeAllHelp`/`afterAllHelp`).
4. **Strictness ratcheting per major, with migration tips** — 13.0.0: excess arguments error, throw on malformed flags, throw on repeated parse with `storeOptionsAsProperties`; 14.0.0: Node ≥ 20, help groups, unescaped negative numbers (CHANGELOG.md:45-92). The project deliberately trades leniency for correctness each major.
5. **Help as overridable class** (command.js:203-220) — `createHelp()`/`configureHelp()`/`configureOutput()` give three customization axes without forking; style* methods (help.js:545-608) enable color.
6. **Option value provenance** (`_optionValueSources`: default/config/env/cli/implied; command.js:38-39, 953-992) — enables `.env()`, `.implies()`, `.conflicts()`, `.mandatory` without a config framework.
7. **Save/restore state for repeated `.parse()`** (13.0.0, command.js:1127-1174) — with explicit guard rails (`storeOptionsAsProperties` forbids re-parse).
8. **Hard `process.exit` by default** with `exitOverride` escape hatch (command.js:508-539) — classic CLI-framework tradeoff: correct exit codes vs. truncation of pending async work; users opt into testability.
9. **Single-shot binary search for suggestions** — Damerau–Levenshtein with maxDistance 3 + 0.4 similarity floor (suggestSimilar.js:1-101).
10. **Triple type-checking** — JSDoc in source + `tsc -p tsconfig.js.json` (checkJS), hand-written `.d.ts` + `tsd` + `tsc` for TS, plus `ts-imports.test.ts` and `esm-imports-test.mjs` at runtime (package.json:21-34).
11. **Formalized release policy** (new in 14.0.3, docs/release-policy.md; #2462) — 12-month security window for the previous major (13.x until 2026-05-18), majors at Node LTS EOL.

## 6. Change Impact Analysis

Given the zero-dependency policy, semver discipline, and event-driven internals, the blast radius of any change class:

| Change class | Blast radius | Gatekeepers | Notes |
|---|---|---|---|
| `parseOptions` behavior changes | **Very high** — every consumer's parsing | tests/options.*, tests/negatives, positionalOptions, parseOptions suites | Only via majors; strictness increases are the project's pattern |
| New builder methods on `Command` | Medium — additive, safe | typings + JSDoc + README + examples + zh-CN docs (all must move together, CONTRIBUTING.md:30-39) | The documented cost of any feature |
| Event/legacy behavior changes | High for old consumers (`command:*`, `.on('--help')`) | deprecated.md lifecycle | Deprecate at one major, remove at a later major |
| Help rendering changes | Medium — WYSIWYG | help.* test files (17+); snapshot-like assertions | Style hooks absorb most custom needs |
| Typings changes | High for TS consumers | tsd + `ts-imports.test.ts` | Drift is the main recurring cost (R3) |
| Dependency addition | **Policy-rejected** | CONTRIBUTING.md:40 | Must be avoided even if locally optimal |
| Node floor bump | Ecosystem-wide, scheduled | release-policy.md | Next expected at v15 |
| Removal of deprecated APIs | Ecosystem-wide, scheduled | docs/deprecated.md | Only at majors; migration tips required |

**Do-not-touch zones** (would break the project's identity): the zero-dependency invariant; the CJS-core/ESM-wrapper duality; the EventEmitter contract (internal bus *and* public legacy API); `process.exit`-based error flow (unless `exitOverride` is the vehicle); the strictness ratchet (never relax an error silently).
