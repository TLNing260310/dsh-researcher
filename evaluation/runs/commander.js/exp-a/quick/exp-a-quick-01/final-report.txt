## 1. Project Identity

**What it is.** Commander is the de-facto standard Node.js CLI framework — "the complete solution for node.js command-line programs" (Readme.md:8, package.json:4). A declarative API: the author describes options, arguments, and subcommands; commander parses `process.argv`, validates strictly, generates help, and dispatches to action handlers or external executable subcommands. Originally authored by TJ Holowaychuk (2011, LICENSE:3); currently maintained by John Gee and Abe Tomoaki (C12, package-support.json:13-15).

**Mission** (reconstructed, not just claimed): be the default, dependable, zero-dependency way to build Node CLIs — strict parsing with helpful errors, automated help, and escape hatches for every opinionated default, so that a CLI written against commander keeps working for a decade. The 12-month maintenance window for the previous major (docs/release-policy.md:10) and the deprecation backlog held since v7 (C14) are direct evidence of this mission.

**User.** Node CLI authors: from a single-file script (examples/split.js) to large multi-command tools (examples/pm*, string-util.js). Scale of adoption is *likely* very large (commander appears in a published audit of npm packages with >10M weekly downloads) — C13, unverifiable this session.

**Value mechanism.** Author declares intent; commander delivers parse + validation + help + dispatch. Value comes from: (a) correctness of a genuinely hard problem (ambiguous CLI grammar — see §3), (b) strictness with actionable errors (`error: unknown option '--fits' (Did you mean --first?)`, Readme.md:95-96), (c) zero-install-cost integration (no deps to audit), (d) escape hatches (exitOverride, configureHelp/Output, allowUnknownOption, storeOptionsAsProperties) so nothing is a dead end.

**Current state.** Maintenance plateau: 14.0.0 (2025-05) shipped the last feature batch (help groups, negative numbers, Node 20); 14.0.1–14.0.3 were fixes/docs/dev-dep bumps. HEAD's two commits are dependabot bumps touching only package-lock.json (C02, verified via `git show`). The project is healthy and at rest.

## 2. Architecture Map

```
index.js ──► lib/command.js (Command, ~2,777 lines — the core)
  │            ├─ extends EventEmitter (node:events)
  │            ├─ lib/option.js    (Option, DualOptions, flag parsing)
  │            ├─ lib/argument.js  (Argument, humanReadableArgName)
  │            ├─ lib/help.js      (Help — help generation, styling, wrapping)
  │            ├─ lib/error.js     (CommanderError, InvalidArgumentError)
  │            └─ lib/suggestSimilar.js (Damerau–Levenshtein suggestions)
esm.mjs ──► named-export wrapper for ESM consumers
typings/  (index.d.ts 1,113 lines, esm.d.mts) + tests (tsd, ts-imports, esm-imports)
```

**Parse pipeline** (C06). `parse()/parseAsync()` → `_prepareUserArgs()` (argv convention auto-detect: node/electron/eval/user, script-name inference) → `_parseCommand()` recursively:
1. `parseOptions()` — single-pass state machine over args (command.js:1748-1895): known options → emit `option:<name>` events; short-flag combos (`-abc`); `--flag=value`; variadic collection; negative-number disambiguation; `--` literal; unknown → routed to `unknown` bucket; positional/pass-through modes truncate processing.
2. `_parseOptionsEnv()` / `_parseOptionsImplied()` — env-var and implied-value filling with source priority.
3. Dispatch: subcommand found → recurse (`_dispatchSubcommand`, incl. `preSubcommand` hooks); default command; help command; missing-command help; action handler with `preAction`/`postAction` hook chains; legacy `command:<name>` events.

**Value/source model.** `_optionValues` map + `_optionValueSources` (`default|env|cli|implied|config`) — the mechanism that makes env-override-default, cli-override-env, conflicts, and dual-option (`--build`/`--no-build`, via `DualOptions`) precedence work without a rule engine.

**Execution model.** Errors → `error()` → `_exit()` → `process.exit` (or `exitOverride` callback). Executable subcommands spawn child processes with extension probing, symlink resolution, inspector-port incrementing, and signal forwarding (C08). Async support: hooks/actions are promise-chained via `_chainOrCall`, not re-architected — one code path serves sync and async (command.js:1481-1541).

**Testing architecture.** Jest + fixtures (incl. extension matrix `.cjs/.mjs/.ts` for executable subcommands); tests grouped by surface area (`options.*`, `args.*`, `help.*`, `command.*`); CI runs `npm test` + `npm run check` (eslint, prettier, tsc on JS via JSDoc, tsd, tsc on TS) across Node 20/22/24 × win/linux/mac (C04, C10a).

## 3. Critical Components

1. **`Command` core / parse pipeline** (lib/command.js) — 65% of runtime code. Everything converges here: `parseOptions` grammar, dispatch precedence (subcommand > help > default > missing-command-help > action > legacy), error taxonomy (`commander.unknownOption`, `commander.excessArguments`, `commander.missingArgument`, etc.). Highest regression risk; most-tested surface.
2. **`parseOptions()` state machine** — the ambiguous-grammar resolver: `-abc` combos, `--opt=val`, optional-arg take-next-unless-option, variadic slurping, negative-number vs `-1` option disambiguation (checks ancestor short options), `--` literal, positional/pass-through modes. Refactored to in-place processing in 14.0.1 (#2409) — recently touched, hence hot.
3. **`Option`/`Argument` + `DualOptions`** (lib/option.js:3-306) — flag-string grammar validation (v13 throws on unsupported flags, incl. dual-long support from 13.1), camelCase attribute names, negate handling, preset/choices/implies/env wiring, and the dual-option value provenance heuristic.
4. **`Help`** (lib/help.js, 747 lines) — complete help generation: usage, groups (14.0), wrapping (`boxWrap`, `formatItem`, `minWidthToWrap`), ANSI-strip width math, and a full `style*` hook surface; extension via `configureHelp()`/subclass (`createHelp`).
5. **Executable subcommand machinery** (command.js:1202-1346) — spawn, extension probing, legacy name fallback, Windows-specific error surfacing, signal forwarding, `incrementNodeInspectorPort`. Platform-sensitive; covered by 6 test files + fixtures.
6. **Typings + JSDoc dual maintenance** (typings/index.d.ts, JSDoc in lib/) — two sources of truth kept in sync by tsc-on-JS, tsd, and TS import tests (C09). A change to any public API touches 4+ artifacts.
7. **Deprecation layer** — 10+ documented deprecated APIs (docs/deprecated.md) still live in code (`.option(RegExp)`, `noHelp`, `.on('--help')`, `.command('*')`, `_args`, `addHelpCommand(string)`, …). Any removal is a major-version event.

## 4. Design Decisions

| # | Decision | Rationale (as evidenced) | Verdict |
|---|---|---|---|
| D1 | **EventEmitter-driven option handling** (`option:` events) | Legacy design (2011), but doubles as the public custom-event API ("Custom event listeners", Readme.md:43) | Constraint, not corrosion |
| D2 | **Zero runtime dependencies** | Verified at code level (C03); color, suggestions, wrapping all hand-rolled to keep the supply-chain surface empty | Core invariant |
| D3 | **Strict by default, escape hatches on request** | Unknown options error (Readme.md:73); v13 made excess arguments an error (CHANGELOG:82); `allowUnknownOption`/`allowExcessArguments` opt back out | Core invariant |
| D4 | **Value-source tracking** | Enables env/implied/conflict semantics without configuration files (command.js:953-972) | Deliberate |
| D5 | **Factory-method extensibility** | `createCommand/createOption/createArgument/createHelp` overrides instead of inheritance-only (command.js:192-204, 316-318) | Deliberate |
| D6 | **JSDoc + hand-written d.ts** | Type-check JS via tsc, ship d.ts; avoids TS source build step | Tradeoff: drift risk (see §5 R1) |
| D7 | **CJS core + ESM wrapper** (`esm.mjs`, exports map) | Single implementation, no dual-package hazard (package.json:45-61) | Deliberate; documented deprecation of direct `commander/esm.mjs` import |
| D8 | **Singleton `program` + `createCommand()`** | Easy start, no global pollution (index.js:7-11) | Deliberate |
| D9 | **Release policy** | Semver; majors ~6 months; Node floor raised at LTS EOL; previous major gets security-only 12 months (docs/release-policy.md) | Core invariant |
| D10 | **Backward-compat debt held across majors** | Deprecations since v7 still live; removal only at majors (v12: default export; v13: multi-char short flags) | Deliberate; amortized at next major |

**Tradeoff scan** (summary): performance is irrelevant for CLI parsing (one pass, O(n)); the real tradeoffs are complexity (parseOptions modes) vs. ergonomics, and compat (D10) vs. cleanup — both consciously resolved in favor of stability. Security/privacy surface is minimal (no deps; env handling reads only author-named vars; CodeQL configured; Tidelift reporting, SECURITY.md).
