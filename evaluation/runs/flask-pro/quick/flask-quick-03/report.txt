## TL;DR

This snapshot is the **upstream Flask source itself** (Pallets), development version **3.2.0.dev**, captured mid-release-prep for the largest architectural change Flask has shipped in years: the **merge of `RequestContext` into `AppContext`** (#5639) plus a **dispatch refactor that passes the context explicitly** (#5815). The snapshot is fundamentally healthy — comprehensive CI (including free-threaded Python 3.13t/3.14t), strict typing, deprecation paths in place — but it is **mid-flight**: the migration machinery is untested, docs teach calls that now raise `TypeError`, and a **known CVE (CVE-2026-27205, missing `Vary: Cookie`)** is present in the code, fixed upstream only *after* this snapshot (3.1.3). Separately, the working tree is **100% dirty with line-ending-only (CRLF) diffs** — a snapshot-provisioning artifact, not a repo defect, but the #1 operational blocker for anyone working in this copy.

**The most important single risk:** `Flask.__init_subclass__`'s legacy-signature shim (`src/flask/app.py:253-307`) — it mutates the `Flask` base class process-wide and re-reads the context from a contextvar, partially undoing the very refactor it's bridging, with **zero dedicated tests**.

## 3. Findings — problems, risks, architectural concerns

### F1 — CRLF-only dirty working tree (snapshot hygiene, HIGH operational impact)
**Evidence:** `git status` shows all 234 tracked files ` M`; sampled diffs across `src/flask/ctx.py`, `LICENSE.txt`, `tests/test_apps/.env`, `docs/make.bat` show *only* `\r` additions — content identical to HEAD. `.editorconfig:8` mandates `end_of_line = lf`; no `.gitattributes` exists.
**Problem chain:** every file diverges from HEAD → `git diff`/`git status` are unusable noise → pre-commit hooks (ruff etc. with `end_of_line=lf`) would rewrite every file → high risk of an accidental mass commit; any real change is indistinguishable from the EOL noise.
**Diagnosis:** this is a snapshot-provisioning artifact (e.g., checkout with `core.autocrlf=true`), not an upstream defect — but it makes the working copy untrustworthy as a workspace. Any analysis tooling that diffs against HEAD will flag the entire tree.
**Direction:** renormalize EOL (re-checkout with `core.autocrlf=input`, or `git add --renormalize`), and add a `.gitattributes` (`* text=auto eol=lf`) so it can't recur. **This is a precondition to doing anything else in this tree.**

### F2 — CVE-2026-27205: missing `Vary: Cookie` (security, externally verified)
**Evidence:** `src/flask/sessions.py:362-364` adds `Vary: Cookie` only when `session.accessed` is True. Werkzeug's `SecureCookieSession` marks `accessed` on `__getitem__`/`get`/`setdefault`/updates — but **not on membership tests or iteration**. A view that branches on `"user_id" in session` produces session-dependent content with **no `Vary: Cookie` header**; a shared cache (CDN/proxy) may then serve one user's personalized response to another (CWE-524). The snapshot's tests (`tests/test_basic.py:571-578`) cover `/get`, `/getitem`, `/setdefault`, `/clear` — exactly the paths that *do* track `accessed` — and **not** the membership path. `CHANGES.rst` contains no 3.1.3 entry, and the last substantive `sessions.py` change predates the snapshot (2025-03-10, `fb541598`), so the fix is absent. External: [IBM bulletin — "Fixed in 3.1.3"](https://www.ibm.com/support/pages/security-bulletinflask-vary-cookie-header-vulnerability-use-cache-containing-sensitive-information-fixed-313#1), [CVE-2026-27205 (opencve)](https://app.opencive.io/cve/CVE-2026-27205). *Caveat: `web_fetch` is unavailable this session, so the exact upstream patch could not be read; confidence .80.*

### F3 — The legacy dispatch shim is the riskiest code in the release (architecture, HIGH)
`Flask.__init_subclass__` (`src/flask/app.py:253-307`) introspects all 11 refactored methods on **every Flask subclass ever defined**, and on detecting an old signature:
1. **Mutates the `Flask` base class itself** — `setattr(Flask, name, add_ctx(base_method))`. This is global, process-wide, and irreversible: one legacy extension subclass redefines how *every* Flask app instance in the process dispatches, including unrelated apps and frameworks built on it.
2. **Stacks on repeat** — a second legacy subclass wraps the already-wrapped base method (functionally OK, structurally accretive).
3. **Reintroduces exactly the coupling the refactor removed** — `add_ctx` fetches ctx via `app_ctx._get_current_object()` (`app.py:99,101`), a contextvar read at call time; the whole point of #5815 was to stop relying on the ambient context during dispatch. Processes containing any legacy subclass silently lose part of the architectural benefit, and `super()`-style calls outside an active context that previously worked now raise `RuntimeError("Working outside of application context")`.
4. **Untested** (C0-6): no tests exercise warning emission, `remove_ctx`/`add_ctx` behavior, double-wrapping, or the no-warning new-signature path.

**Corrosion check:** the merge itself is legitimate evolution (the old two-context model had real ordering/reuse bugs — cf. #5797 "push preserved contexts in correct order"). The shim's *global base-class mutation* is the corrosion-prone part: it's a local-compatibility fix whose side effects leak process-wide. → **INVESTIGATE** (design question), **BUILD** (tests) — see §5.

### F4 — Long-tail semantic changes without deprecation coverage (architecture, MEDIUM)
- **Fresh `g` per request** (`ctx.py:289-292`, `CHANGES.rst:10-11`): an outer manually-pushed `app.app_context()` no longer shares `g` with requests dispatched inside it. Correct direction, but a *silent* behavior change (no warning possible) for the documented testing/scripting pattern.
- **Lazy session loading** (`ctx.py:294-296`): `open_session` moves from push-time to first-access — interacts with F2 and with extensions that expected the session to exist during `before_request` (it still does, via `ctx.session`… but only if accessed).
- **sansio/Quart drift** (C0-9): the sansio base class keeps old no-ctx signatures while concrete `Flask` adds `ctx` — the shared interface no longer matches, and Quart must absorb the same refactor separately.

### F5 — Documentation teaches broken code (docs, MEDIUM-LOW)
`docs/shell.rst:23-29` still teaches `RequestContext` (deprecated alias — works, but obsolete), and **`docs/shell.rst:52` (`app.preprocess_request()`) and `:61` (`app.process_response(app.response_class())`) plus `docs/testing.rst:317` are now `TypeError`s** in 3.2 — those methods require `ctx`. `docs/api.rst:309-317` is correctly updated, so the drift is partial — a user following the shell/testing docs gets a runtime crash on the exact API the release changed. Sphinx's `-W` build won't catch it (examples aren't doctested).

### F6 — Typing blind spot for deprecated aliases (MEDIUM-LOW)
`flask.ctx.RequestContext` and `flask.globals.request_ctx` exist only via module `__getattr__` (`ctx.py:504-516`, `globals.py:65-77`), invisible to mypy/pyright under this repo's own strict config (`pyproject.toml:127-146`). Typed extension code using the aliases keeps working at runtime but breaks statically — a poor deprecation experience for the ecosystem the deprecation is meant to protect.

### Non-findings (checked, cleared)
- CVE-2025-47278 (fallback-key ordering): **fixed** in-tree (`sessions.py:321-326`).
- CI robustness, dependency pins, typing strictness, test hygiene (`filterwarnings = error`): strong.
- Free-threaded testing (3.13t/3.14t): a positive bet, no GIL-dependent code path identified in the reviewed dispatch/context code.

**BUILD** (evidence sufficient → hand to Plan):
1. Backport the CVE-2026-27205 fix (ensure `Vary: Cookie` on session-dependent responses regardless of access-tracking path) + regression tests incl. membership-test path.
2. Add dedicated tests for the legacy-signature shim: warning emission, `remove_ctx`/`add_ctx` arg handling, repeated legacy subclasses (stacking), new-signature no-warning, and no-global-regression when a legacy subclass coexists with plain apps.

4. Declare the deprecated aliases for type checkers (TYPE_CHECKING re-exports/stubs) so typed extensions degrade gracefully.

**INVESTIGATE** (not for development yet):

- sansio/Quart alignment plan for the new dispatch signatures.

**DON'T BUILD:** reverting or re-scoping the context merge; additional deprecation machinery; any feature work beyond release-readiness — feature count is not the bottleneck; migration completion and the security fix are.
