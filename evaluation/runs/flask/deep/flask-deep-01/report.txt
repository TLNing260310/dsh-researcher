## 4. DIAGNOSE — Problem Chains (problem → impact → evidence → intervention)

1. **CRLF working tree (C2)**. Impact: any diff, patch, or PR generated from this workspace is 100% line-ending noise; a coding agent editing one file corrupts the comparison baseline. Intervention: normalize to LF before any build step. This is a snapshot-harness defect, not a Flask defect.
2. **`update_template_context` shim gap (C22)**. Chain: 3.2 changed signature `(self, context)` → `(self, ctx, context)` → subclass override with old signature receives the `AppContext` as `context` → `context.update(...)` → `AttributeError` at template render, no warning. Impact: silent breakage of a documented override point (the method is in the public API surface); the *entire point* of the shim was to prevent exactly this. Intervention: add it to the shim list + test.
3. **Broken docs examples (C17/C18)**. Chain: refactor changed call-site signatures → docs' canonical "call dispatch manually" recipes crash with `TypeError` → users following docs get runtime failures; Flask's docs are part of its product. Intervention: pass the context in examples (`with app.test_request_context(...) as ctx: app.preprocess_request(ctx)`).
4. **Untested shim + untested new semantics (C11-C15)**. Chain: the riskiest new code (runtime signature introspection + **global base-class mutation** `setattr(Flask, ...)`) has zero tests; multiple old-style subclasses cause wrapper accumulation (benign today, fragile); staticmethod/classmethod overrides would be broken by `remove_ctx`; post-class monkeypatching bypasses the shim entirely. The headline semantics (fresh `g`, lazy session, signals per request) are only indirectly tested. Intervention: focused regression tests.
5. **Malformed RST (C7) + no docs CI (C8)**. Chain: typo → docutils warning → `sphinx-build -W` failure → ReadTheDocs/tox docs break; CI never notices because tests.yaml has no docs job. Intervention: fix roles; consider a docs job.
6. **Undocumented behavior changes (C19/C20/C21)**. Chain: merged context → changed error strings, changed teardown/signals timing, fresh `g` → docs describe the old model → user confusion and support burden, especially for extension authors (extensiondev.rst:182-187 still implies `g` persists across a request inside a `with app.app_context():` block). Intervention: docs updates + a 3.2 upgrade note.
7. **Ecosystem risk (C4/C10)**. Chain: "If an app context is already pushed, it is not reused when dispatching a request" → extensions that scope state to the app context (SQLAlchemy-style scoped sessions, `g`-cached resources) now see per-request contexts, double teardown, per-request signals. Intentional and documented in CHANGES.rst:8-11, but the blast radius is unmeasured. Intervention: INVESTIGATE against major extensions; upstream issue #5639 exists.

## 5. TRADEOFF ANALYSIS

- **Context merge**: cost = deliberate breaking change for the outer-context-reuse case; benefit = one push/pop path, one ContextVar, simpler async semantics, foundation for future work. Net: sound; the missing piece is *communication* (docs/upgrade guide), not the design.
- **Compat shim**: cost = complexity + global side effect + heuristics; benefit = subclass users migrate smoothly. The alternative (hard break) was worse; but a shim that misses `update_template_context` and is untested is a liability that must be either completed or explicitly scoped.
- **Lazy session loading**: cost = timing shift for custom session interfaces (`open_session` may now run with `url_rule` set, or from inside URL converters — test_converters.py:29-42 pins converter access); benefit = no session I/O when unused. Acceptable; needs one discriminating test.
- **No more engineering is better**: the right next actions are small and targeted. A "rewrite the docs" or "add features" push would be wrong for a project whose main risk right now is compat certainty before a release.
