## Most important problem: the `__init_subclass__` compat shim (src/flask/app.py:253–307) is defective

This is the highest-risk code in the snapshot. It exists to keep the extension ecosystem (which commonly overrides `process_response`, `handle_exception`, `dispatch_request`, `do_teardown_request`, `preprocess_request`, `full_dispatch_request`, …) working after the signature change. I verified these defects by simulating the exact logic:

1. **Global mutation of the `Flask` base class.** Defining *any* old-signature subclass runs `setattr(Flask, name, add_ctx(base))`, permanently rewriting `Flask.<method>` process-wide. `inspect.signature(Flask.process_response)` degrades to `(*args, **kwargs)` for all code, and behavior becomes order-of-import-dependent across unrelated libraries.
2. **Spurious DeprecationWarnings cascade down hierarchies.** A subclass that inherits from a patched subclass *without overriding anything* still trips the check: `getattr(cls, name)` returns the parent's `remove_ctx` wrapper, which is not the (now-patched) base method and whose `(*args, **kwargs)` signature never matches the `ctx` test → warning + re-wrap at **every inheritance level**. Simulation confirmed warnings for `ChildOfOld` and `GrandChild` classes that define nothing.
3. **Repeated re-wrapping** (`add_ctx(add_ctx(...))`) on each patch — functionally idempotent but grows the call chain and the pollution.
4. **Zero test coverage of the old-signature path.** `tests/test_subclassing.py` only exercises the new signature; the compat path most likely to break real extensions is untested.

The mechanism works in the common single-subclass case, but as written it is fragile and will emit confusing warnings for innocent third-party subclasses.

## Other problems and risks

**Documentation drift (verified):**
- `docs/shell.rst` still teaches the **old signatures**: `app.preprocess_request()` (line 52) and `app.process_response(app.response_class())` (line 61) now raise `TypeError`; lines 23–29 reference the deprecated `RequestContext` with now-unresolvable `~.RequestContext` roles.
- `docs/api.rst:304` claims `app_ctx` is "only available when a request context is active" — wrong; it's available in any app context (e.g. CLI commands).
- `docs/appcontext.rst:84–89` shows "Working outside of request context." for the app-context-without-request case, but the actual error is now `RuntimeError("There is no request in this context.")` from `AppContext.request` — the two messages differ by whether *any* context is active.
- Docstring typos in app.py:1475/1490: `:data:`g:,` (missing backtick → broken docs rendering).

**Changelog gaps for real behavior changes:**
- Lazy session loading — session errors now surface at first access (often `process_response`) instead of at push.
- Per-request teardown semantics — with an outer `app.app_context()` active, `teardown_appcontext` and a fresh `g` now run per request (test_appctx.py updated to expect `[None, None]`); previously the outer context was reused. Breaking for tests/extensions relying on shared `g`.
- `AppContext.pop()` no longer falls back to `sys.exc_info()` when called without an argument.

**Minor ctx.py issues:** dead second `self._cv_token is None` check in `pop()` (line 456); `push()` increments `_push_count` before `_cv_app.set()`; `match_request()` crashes on `None` adapter if called directly; cross-thread push/pop silently miscounts.

**Ecosystem risk:** the 12 changed signatures are the most commonly overridden extension hooks, and the shim is the only mitigation. Positives: the refactor itself is sound (`_push_count`-guarded push/pop, module `__getattr__` aliases, `AppContext.from_environ`, preserved `FlaskClient` preserve-context flow, `stream_with_context`, `copy_current_request_context`), no internal uses of the deprecated aliases remain, and the CI matrix (py3.10–3.14 incl. free-threaded, min/dev deps, Windows/macOS/PyPy, `filterwarnings=error`) is strong.

## Recommended next actions (priority order)

1. **Rework the shim** — only inspect methods defined in `cls.__dict__` (skip inherited); stop mutating `Flask` globally (per-class wrapping or a patched-name registry); guard against double-wrapping; add tests for old-sig override with `super()` call, two old-sig subclasses, a non-overriding subclass of a patched subclass (no warning), and unchanged base signatures.
2. **Fix docs** — shell.rst examples (`ctx` args, `AppContext`), api.rst/appcontext.rst messages, docstring typos.
3. **Expand CHANGES.rst** with the lazy-session, per-request teardown/`g`, and `pop()` changes.
4. **Add regression tests** for the old-signature compat path.
5. **Minor ctx.py cleanups** (dead check, push ordering, `match_request` guard).
6. **Pre-release verification** — full tox suite incl. `tests-dev` and typing, docs build with `-W`, and import smoke tests of common Flask subclasses.
