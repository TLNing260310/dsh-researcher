## 5. Risk Map

**R1 — ACTIVE DEFECT (the only content change; severity: high, trigger: certain-on-user-error).**
`lib/command.js:2058-2062`:
```js
missingMandatoryOptionValue(option) {
  // MUT-06 (synthetic): message now includes option flags.
  const message = `error: required option '${option.flags}' not specified (flags: ${option.flags()})`; // MUT-06 (synthetic)
  this.error(message, { code: 'commander.missingMandatoryOptionValue' });
}
```
- `option.flags` is a **string property** (`lib/option.js:12`), so `${option.flags()}` throws `TypeError: option.flags is not a function` **before** `this.error()` runs.
- Consequence: whenever a user omits a mandatory option (`.requiredOption()` / `.makeOptionMandatory()`), the library **crashes with an internal TypeError** instead of printing `error: required option '...' not specified` and exiting 1. `exitOverride()` is bypassed (no `CommanderError` is ever constructed); `showHelpAfterError` output never happens. Embedding apps catch an uncaught TypeError, not a catchable CommanderError.
- Provenance: explicitly labeled `MUT-06 (synthetic)`; grep across all 223 files finds the marker **only** here — injected, non-upstream (C0-004). Call site: `_checkForMissingMandatoryOptions()` (`lib/command.js:1675-1687`), which runs in both action-handler and executable-subcommand paths.
- Detected by: `tests/command.exitOverride.test.js:290-308` (asserts type + exitCode 1 + code + exact message) and `tests/command.showHelpAfterError.test.js:43-54` (asserts code + help-after-error output) — both **fail**. `tests/options.mandatory.test.js:118-159` passes only incidentally (`toThrow()` accepts a TypeError).
- Doc contradiction: `Readme.md:359` and `Readme_zh-CN.md:340` show the canonical message the code can no longer produce — undermining the project's core "documented predictability" value.

**R2 — Test-robustness blind spot (pre-existing, exposed by R1):** only 2 of the ~110 test files assert message/type/code contracts on the mandatory-option path; the rest are throw-tolerant. The suite *does* catch this mutation, but a marker-free variant with a message-only change would slip past every test except the same two.

**R3 — Provenance loss (environmental):** flattened git history (C0-002 r2). No blame, no diff, no audit trail; every future change is indistinguishable from upstream content except by content analysis. Any merge of upstream v15 code onto this snapshot would silently carry the defect forward.

**R4 — Version drift:** snapshot frozen at 14.0.3 while upstream ships v15 (C3-001); 14.x is now the *old* major with a finite security window (release-policy). If this tree is ever used as a live codebase, it misses upstream fixes.

**R5 — Pre-existing hygiene (unchanged):** manual env cleanup in tests (`options.env.test.js:16-20,44-48`), ESM smoke test outside jest (`esm-imports-test.mjs`), thin direct coverage of the executable-subcommand success path (C2-013, Likely); no coverage gate (C2-006).
