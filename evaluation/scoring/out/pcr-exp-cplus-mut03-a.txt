**Parse pipeline** (all in `lib/command.js`): `parse/parseAsync` → `_prepareForParse` (first call `saveStateBeforeParse`, later calls `restoreStateBeforeParse` — enables repeated `.parse()`) → `_prepareUserArgs` (argv conventions: node/electron/user/eval; derives `_scriptPath` and default name) → `_parseCommand` → `parseOptions` (split into operands/unknown; handles `--`, `-abc` groups, `--opt=val`, negative numbers, positional/pass-through modes) → env + implied option values → dispatch: subcommand (`_dispatchSubcommand`), help command (`_dispatchHelpCommand`), default command, action handler, or legacy `command:*` events. Life-cycle hooks (`preSubcommand/preAction/postAction`) are chained through the promise-aware `_chainOrCall*` family so sync and async parse share one path.

**Executable subcommand path (the mutation site)** — `_dispatchSubcommand` (command.js:1352) → `_executeSubCommand` (command.js:1202):

```

  ├─ 1. mandatory/conflicting-option checks (before spawning)
  ├─ 2. determine executableFile = subcommand._executableFile | "parentName-subName"
  ├─ 3. resolve executableDir (script-path-relative, realpath for symlinked bins)
  ├─ 4. findFile(baseDir, baseName):                    ← MUTATION SITE (line 1205)
  │      a. exact path exists?  → use it
  │      b. baseName already has a known extension? → stop
  │      c. probe baseName+ext for ext in sourceExt (ORDER = preference)  ← mutated order

  ├─ 6. launchWithNode = sourceExt.includes(extname)    (set membership — order-independent)
  ├─ 7. spawn: node (with --inspect port increment) vs direct; win32 vs unix
  └─ 8. signal forwarding (SIGUSR1/2, SIGTERM, SIGINT, SIGHUP); close→process.exit(code)
        or exitCallback(CommanderError 'commander.executeSubCommandAsync'); ENOENT/EACCES
        → _checkForMissingExecutable; runningCommand tracking
```

## 4. Design Decisions

- **EventEmitter-driven option assignment** (command.js:720-730): parsing emits `option:<name>` / `optionEnv:<name>` events — extensible, but value assignment is event-listener side-effect.
- **State save/restore for repeated `.parse()`** (`saveStateBeforeParse`/`restoreStateBeforeParse`, command.js:1141-1174) — lazy, per-command; guarded against `storeOptionsAsProperties` (the guard is what MUT-01 removes).
- **Extension probing order = append-by-history** (CL-03): `.js` original; `.ts`/`.tsx` added v6.2.0 (#1368); `.mjs`/`.cjs` added v7.1.0 (#1449). Resulting preference: **TypeScript variants win over ESM variants when both exist and no `.js` exists**. The order is *intentional in effect* (ts-node users get their `.ts` file) but *undocumented* — README says only "trying common file extensions, like `.js`" (Readme.md:703, CL-09).
- **Executable resolution hierarchy**: explicit `executableFile` → `command-subcommand` name in `executableDir` → legacy script-name prefix (command.js:1249-1261); local file beats PATH; realpath resolves symlinked global installs.
- **Process-coupling by design**: spawned subcommands inherit stdio, forward signals, and `process.exit()` with the child's code unless `exitOverride` is set (command.js:1267-1342).
- **Error strategy**: `error()` → `_exit()` → `exitOverride` callback or `process.exit`; stable `commander.*` codes (the compatibility surface mutated in MUT-05/06).
- **Corpus conventions** (this snapshot's meta-layer): every injected change is (a) single-hunk, (b) self-marked `// MUT-0x (synthetic): …`, (c) invisible to git, (d) line-count-preserving. The MUT-03 injection additionally uses escaped dots — see Risk R3.

### Previous assumptions that no longer hold

1. **"MUT-02 is a pristine baseline of commander.js" (H3 — invalidated in this session).** It is not: it carries the configureHelp `base`-merge mutation. Any comparison that treats MUT-02 as upstream truth is wrong in the help-configuration area.
2. **"`configureHelp()` accepts an optional base-class parameter and preserves descriptors"** (the MUT-02 api_contract surface). **No longer holds in MUT-03** — `configureHelp(configuration)` stores the configuration object verbatim; `createHelp()` always uses the `Help` base class. Code written against the MUT-02 contract (e.g., `configureHelp({ base: MyHelp })`) silently loses the base-class override here.
3. **"Executable subcommand probing prefers TypeScript over ESM"** (upstream behavior, pinned by search.test.js:312). **No longer holds in MUT-03** — `.mjs`/`.cjs` now win over `.ts`/`.tsx`. This is the single behavioral contract inversion this snapshot introduces.
4. **"The mutation is invisible to all tooling."** Partially false: `npm run check` (eslint `no-useless-escape`) flags line 1205 — though only because of the escaped-dot artifact, not the order change.
5. **"Git history can reveal what changed."** Never held for this corpus and still does not: single squashed commit; the injection must be found by content comparison (as done here).
6. **"The extension set is identical across the corpus."** No longer true: MUT-03 is the only snapshot whose `sourceExt` differs.

### Blast radius of the change

- **Users**: only projects with git-style executable subcommands *without* a `.js` variant and *with ≥2* extension variants for the same name. Single-variant projects (the overwhelmingly common case, e.g. all lookup fixtures) are unaffected.
- **Tests**: no assertion changes behavior (R2); the hard-coded order at search.test.js:312 still matches upstream, so the suite stays green under both orders (test run 未验证 — sandbox is read-only).
- **Docs**: unaffected (order was never documented).
- **Tooling**: eslint failure in `check` (R3); tsc/prettier unaffected.
- **Downstream patch workflows**: any diff-vs-MUT-02 patch now carries both the MUT-03 hunk and the absent-MUT-02 hunk — applying it to the wrong base corrupts a snapshot (R5).

## 7. Decision Memo

**The change at `lib/command.js:1205` is CORROSION, not evolution.** It is a synthetic, self-marked mutation that inverts an intentional (if undocumented) upstream preference — TypeScript executable subcommands win over `.mjs`/`.cjs` — and can silently cause a different file to execute than upstream would choose. It is not a bug fix, not a feature, and not a refactor; the marker comment states its provenance explicitly (CL-02). The upstream order is evidenced by five sibling snapshots, the in-repo test pin, and the CHANGELOG history of how the list was built (CL-03).

**Decisions:**

1. **BUILD — restore the upstream order.** If this workspace is meant to represent upstream-faithful commander.js (which the corpus framing implies), the defect is confirmed with near-certainty: revert `sourceExt` at `lib/command.js:1205` to `['.js', '.ts', '.tsx', '.mjs', '.cjs']`. Single-line, surgical, zero API change. Confidence 0.98.
2. **BUILD (optional, upstream-value) — pin the preference with an order-sensitive regression test.** The suite's order-insensitivity is a genuine upstream gap (R2): a test asserting `existsSync` call *order* (or a fixture dir with both `foo.ts` and `foo.mjs`) would have caught this mutation and would be a legitimate improvement to commander.js generally. Confidence 0.80. (If the snapshot must remain mutation-intact for evaluation purposes, this item should be skipped — see do_not_touch.)
3. **DON'T BUILD — nothing else.** No other component is affected; docs, typings, and the other 222 files require no change. Do not "improve" the search logic, do not normalize the string escaping without restoring the order (that would mask R3 while keeping the defect), do not remove the `// MUT-03 (synthetic):` marker (corpus metadata).
4. **INVESTIGATE — two items I could not execute in this read-only session**: (a) actually running `npm test` and `npm run check` against MUT-03 to confirm the predicted pass/fail split (R2/R3); (b) fetching upstream T0 `bf35c5f9` (web provider unavailable) to upgrade CL-03 from C3 to C4. Neither blocks the decision; both would harden the evidence.

**Why now**: the snapshot is explicitly a change-detection artifact; the mutation is located, evidenced, and its blast radius is fully mapped — the cost of acting is one line, the cost of ignoring it is a silent behavioral drift in a library with millions of installs.
