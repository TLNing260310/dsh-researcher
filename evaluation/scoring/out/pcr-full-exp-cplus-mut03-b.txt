## (4) Design Decisions

- **Zero production dependencies** — stated and enforced (CONTRIBUTING.md:40; C3).
- **Strictness by default** — unrecognised options, excess/missing arguments, missing mandatory options all error (C2); `allowExcessArguments` false since v13 (CHANGELOG:82).
- **Options stored separately from command properties since v7**; `storeOptionsAsProperties()` is the legacy escape hatch (C8).
- **Executable subcommands = child processes** (not in-process): source-extension resolution, signal forwarding, inspector-port increment (C13). The `sourceExt` precedence order (`.js` → `.ts` → `.tsx` → `.mjs` → `.cjs`) is an implicit sub-decision: **TypeScript sources preferred over ESM/CJS bundles** — the very decision MUT-03 inverts.
- **Multiple `.parse()` calls** supported via save/restore state; throws under `storeOptionsAsProperties` (C12).
- **Lazy help option/command creation** (C7); **release policy** — majors ~every 6 months, node minimum at LTS EOL, 12-month security window for old majors (C5); **security via Tidelift** (C14); **deprecated-but-supported backlog** tracked in docs/deprecated.md (258 lines, C15).

### 6b. Impact of the mutation (problem chain)

- **What breaks:** only when `_executeSubCommand` searches an `executableDir` where two same-stem candidate files with different source extensions coexist. Pristine precedence `.js > .ts > .tsx > .mjs > .cjs`; mutated `.js > .mjs > .cjs > .ts > .tsx`. Changed precedences: `.ts`/`.tsx` now **lose** to `.mjs`/`.cjs` (e.g. `pm-search.ts` + `pm-search.mjs` → pristine runs the TypeScript source, mutated runs the ESM bundle).
- **Who is affected:** the subset of commander's huge user base using executable subcommands with co-located TS source and JS bundles — rare, but the exact configuration upstream's order was designed for. The failure mode is **silent**: a different file executes with no error.
- **Detection status:** invisible to the suite (C39): the search test checks each extension is probed (order-insensitive `toHaveBeenCalledWith`); lookup fixtures are extension-less/`.js` only; no documentation pins the order (Readme.md:703 says only "common file extensions, like `.js`"), so no doc contradicts it (C41).
- **Severity:** low blast radius, **but this is a deliberately introduced divergence** in a library whose entire value proposition is *predictable, documented parsing behavior*. Leaving it in place converts an evaluation fixture into a real behavioral regression.
