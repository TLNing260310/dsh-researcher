## 4. Design Decisions

The design principles that make the mutation identifiable as corrosion:

- **Error codes are a stable semver contract.** `commander.invalidArgument`, `commander.unknownOption`, etc. are pinned by tests and documented. The mutation introduces `commander.invalidArgumentValue`, a code that exists **nowhere else** in the tree (grep: 1 hit, lib/command.js:608) and is not in typings, docs, or CHANGELOG.
- **Programmer errors propagate raw.** Upstream deliberately rethrows non-`CommanderError` exceptions from user callbacks so real bugs (TypeError, etc.) surface as-is; the test *"when custom processing for argument throws plain error then not CommanderError caught"* (argument.custom-processing.test.js:168–187) pins this. The mutation's `else if` wraps them into a polite `CommanderError`, **masking programmer bugs** — a design regression, not an improvement.
- **User-facing errors are routed through `error()` → `outputError`/`exitOverride`/`showHelpAfterError`.** The README documents the exact output contract (`error: option '-d, --drink <size>' argument 'huge' is invalid. Allowed choices are …`, Readme.md:448; `throw new commander.InvalidArgumentError('Not a number.')`, Readme.md:475). The mutation bypasses this routing entirely.
- **Zero-lint-escape discipline.** The repo runs `eslint:recommended` + tseslint in CI with only 11 targeted escapes in lib. The mutation ships unreachable code and an unused variable — both hard errors under the project's own lint config.
