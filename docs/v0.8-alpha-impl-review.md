## #1. Boundary Check — Cognition State 是否会导致 Memory 漂移 / Agent 增强 / Report 缓存化?

### 1.1 Memory 漂移风险:**否,条件成立**

Cognition State 被判定为"Memory 系统"的充要条件(会漂移):
- (a) host 自动持久化并**自动回灌**到新会话;或
- (b) 成为 Researcher 可写的第二存储(绕过零写契约);或
- (c) 改变会话日志作为唯一事实源的地位。

实现计划的事实:
- 导出器是 **host-plane 投影**(从会话日志折叠),**不是写入方**:导出器只读 session.events.json,输出 cognition-state.json 到评估目录,不注册任何工具、不注入任何 prompt、不触碰项目文件系统。
- 回灌仍走现有 `importState` 工具调用(模型自驱,evaluator 在实验中显式注入)—— **不新增自动回灌路径**。
- 会话日志仍是唯一事实源;cognition-state.json 是派生视图(可随时由日志重建,`fold_replayable`)。

**判定:不构成 Memory 漂移,前提是(写死在实现约束中):导出器不注册工具、不自动加载、不参与任何 session 启动。**

### 1.2 Agent 增强风险:**否**

- 导出器/Diff 是 host 脚本,零工具注册、零 prompt 注入、零模型工具面变化。
- 唯一"模型侧可见"的变化:实验 run-2 经 `research_checkpoint importState` 收到 T0 export —— 这是**现有工具、现有参数**(importState 已在 research-state v2.1 中,非新增)。
- 不改变 Researcher 的能力边界(无 shell、无 write、永拒桩原样)。

**判定:零 Agent 增强。**

### 1.3 Report 缓存化风险:**是,这是唯一真实风险 —— 必须有对抗设计**

- 实证显示当前 research-state 实际角色 = report cache(DECISION 阶段批量提交 16 条,为附录服务)。若 Cognition State 导出器只是"把报告附录结构化为 JSON",它将成为**报告缓存的正式化**,而非认知状态。
- **对抗设计(写死)**:cognition-state.json 必须包含 **evidence_fingerprints**(blob 指纹)与 **freshness**(snapshot commit + 生成时间)—— 这两个字段使状态**可对账、可失效**。一个只能被展示、不能被对账的状态是 cache;一个可以被机械判定"哪些 claim 已过期"的状态才是 cognition state。
- 验收红线:导出器输出**不含指纹字段 → 该实现视为 Report 缓存化,否决**。

**Boundary Check 结论:Memory 漂移无、Agent 增强无、Report 缓存化有风险但可用指纹字段对抗。计划总体在边界内。**

```json
  "run": "#N",

  "claims": [{
    "id": "C07",
    "statement": "Option values are source-tagged ...",
    "tier": "C2",
    "verdict": "Known",
    "confidence": 0.9,
    "revision": 3,
    "evidence_anchors": [{
      "ref": "command.js:953-961",
      "file": "lib/command.js",
      "blob_sha256": "a3f9c2...",
      "line_span": "953-961"
    }]
  }],
  "dependencies": {
    "claims": ["C07", "C08"],
    "hypotheses": [{ "id": "H2", "status": "active", "dependsOn": ["C07"], "revision": 1 }],

  "freshness": {

```

### Schema 合规检查

| 要求 | 字段 | 判定 |
|---|---|---|
| claims | claims[] | ✅ |
| evidence anchors | claims[].evidence_anchors[](ref/file/blob_sha256/line_span) | ✅ 指纹已内置 |
| dependency | dependencies(claims/hypotheses/views,逐字段来自现有状态) | ✅ |
| freshness | freshness(generated_at/snapshot_commit/source_log/fold_replayable) | ✅ |
| user memory | 无任何 user 标识/偏好/个人数据 | ✅ 禁止 |
| planning | 无 BUILD/计划/下一步字段 | ✅ 禁止(BUILD 分类在 PCR 中,不在状态里) |
| autonomous action | 无 action/execute/decision 字段 | ✅ 禁止 |

**Schema Review 结论:通过。最小、纯认知、可对账、零越界。**

## #3. Export Design — 是否可完全作为 host-plane projection?

**判定:可以,且这是唯一允许的形式。** 事实依据:

1. **纯函数可复用**:`research-state/index.js` 的 `__test` 导出包含 `makeState / applyCheckpoint / parseCheckpointArgs / fullExport / importState / projection / foldCheckpointEvents`(第 339 行)—— 全部是纯函数,`apply()` 之外可直接 require。导出器只需 `require('../researcher/plugins/research-state/index.js').__test.foldCheckpointEvents`,**不执行插件装配、不注册工具**。
2. **数据源已归档**:Experiment A 的 12 个 `session.events.json` 已含全部 research_checkpoint 的 tool/call 事件(实证:21 次调用)。导出器 = `fold(events) → format(cognition-state.json)`,纯计算。
3. **不修改 runtime**:导出器放 `evaluation/scoring/`(与 score-v11.js 同层,**不是** `evaluation/runtime/` —— 后者是 lock-covered(eval_runtime sha256Dir),新增文件会破坏锁;scoring/ 不在锁内)。
4. **零 runtime 改动**:不碰 eval-headless.mjs、preset、patch、research-state 插件本体。
5. **零写契约不变**:导出器写评估目录(非项目树、非会话日志),Researcher 侧无任何新写入通道。

**Export Design 结论:host-plane projection 完全可行;约束 = 放 scoring/ 目录、只 require __test 纯函数、输出只含 schema v1 字段。**

## #4. Diff Design — Cognition Diff(回答"哪些已有认知失效",非预测 bug)

### 4.1 定义(机械对账,非预测)

Cognition Diff 回答:**给定当前 workspace 与一份 cognition-state.json,哪些 claim 的证据锚已变化,因此哪些既有认知应标记失效候选。** 它不声称"这里有 bug",只声称"你之前相信 X 所依据的代码已变,需重新验证"。

### 4.2 算法(纯机械)

```
输入: cognition-state.json + workspace(可 git 解析)
对每条 claim 的每个 evidence_anchor:
    current_blob = sha256(workspace 中 file 的当前 blob)
    if current_blob != anchor.blob_sha256:
        anchor → STALE
    if claim 的所有锚皆 STALE(或文件缺失):
        claim → stale-candidate
        (依赖它的 hypothesis/view 经 dependentsOf 传播 → affected)
输出:
    { stale_claims: [...], affected_hypotheses: [...], unchanged_claims: [...],
      unverifiable_anchors: [...](文件删除/无法解析,单独列出) }
```

### 4.3 语义边界(写死)

- **是**:失效候选的机械判定(实验真值、freshness 输入)。
- **不是**:bug 预测(不输出"这里会坏");不是修复建议;不是 claim 内容的重评估(模型职责)。
- **不做**:自动修改任何状态;输出仅供 evaluator/实验消费。

### 4.4 用途

1. **Experiment C+ 状态臂的机械真值**:注入 mutation 后,哪些 claim 应失效由 diff 判定,不依赖 evaluator 主观 → H2 的可复现裁决。
2. **v0.9 freshness gate 的输入**(延期)。
3. **对 Experiment A 的回顾性对账**:验证 A 中 137 claims 的证据锚指纹(若 A 的 claims 无有效锚,该事实本身是发现:报告缓存化实证)。

**Diff Design 结论:通过。机械、可复现、非预测、零副作用。**

## #5. Stop Condition Review — H2 失败时删除什么

> 与 principal-decision / principal-verdict / v0.8-alpha-gate 一致,此处给出模块级清单。

### KEEP(无论 H2 结果,保留)

| 模块 | 理由 |
|---|---|
| 只读能力面边界(tool-restrict/git-read/永拒桩) | 定位与信任基础,独立于 H2 |
| 证据纪律(C0–C4 + 裁决态,methodology Module 2) | 产品本体,不依赖状态机 |
| 风险地图 + BUILD/DON'T BUILD/INVESTIGATE(Module 5) | 报告质量特征,独立价值 |
| PCR 双层模板(7 节 + 附录) | 展示层,独立价值 |
| research_doctor 证书(7 项检查) | 可审计性,独立价值 |
| evaluation 全部冻结产物与失败记录 | 反例资产,禁删 |

### ADD(本阶段,全部 host 侧)

| 模块 | 位置 | 说明 |
|---|---|---|
| cognition-state 导出器 | `evaluation/scoring/cognition-state-export.js` | require __test 纯函数,输出 schema v1 |
| evidence 指纹计算 | 导出器内置 | blob sha256;无指纹 = Report 缓存化,否决 |
| cognition-diff.js | `evaluation/scoring/cognition-diff.js` | 机械失效判定,实验真值 |
| doctor 第 8 项检查(报告↔状态一致性) | research-doctor 新增检查项(后续,先实验后产品) | DEFER 到实现验证后 |

### DEFER(v0.9+,取决于 H2 结果)

- Memory Bridge / capsule 自动持久化
- Cognition Handoff 产品化(实验期只用 export/importState)
- 真实窗口漂移(T0→T0+n)
- Structural Evidence 集成
- Claim Delta 深化

### REMOVE(若 H2 失败,双仓库确认后)

- research-state 依赖图/失效传播/版本化**作为产品价值**
- Memory Bridge、Claim Delta、Cognition Handoff 产品化
- 跨会话方向的一切计划(roadmap v0.9 相关条目)

**Stop Condition Review 结论:删除清单明确;KEEP 的模块都有独立价值,不因 H2 失败而丧失 —— 降级路径干净。**

## 最终判断:是否批准进入实现阶段

### 批准(有条件)

**批准范围(v0.8-alpha 最小实现,host 侧)**:
1. `evaluation/scoring/cognition-state-export.js`(schema v1,含指纹);
2. `evaluation/scoring/cognition-diff.js`(机械失效判定);
3. 对 Experiment A 12 个归档日志的回顾性导出验收(一致率、可重放)。

**批准条件(写死,违反即停止)**:

| # | 条件 | 违反后果 |
|---|---|---|
| C1 | 导出器只 require `__test` 纯函数,不装配插件、不注册工具 | 停止,改为纯投影 |
| C2 | 输出 schema 只含 claims/evidence_anchors/dependencies/freshness;无 user memory/planning/action | 停止,按 schema v1 重做 |
| C3 | 导出器/Diff 放 `evaluation/scoring/`(非 runtime/,避免破坏 eval lock) | 停止,移动文件 |
| C4 | **evidence_fingerprints 必须存在**;缺失即 Report 缓存化 | **停止,否决该实现** |
| C5 | 不修改 research-state/research-doctor/persona/PCR/prompt/protocol | 停止,回滚 |
| C6 | 不实现 Memory Bridge、不自动回灌、不新增 agent 工具 | 停止,回滚 |

**不批准的范围**:任何 Agent 侧改动、Memory 系统、prompt/PCR/protocol 修改、benchmark 扩展、第二轮预算承诺。

**批准的理由(证伪导向,非乐观)**:
- 门槛审查(v0.8-alpha-gate)已确认:引擎合格、结构可补、禁令零触碰;
- 本计划审查确认:host-plane projection 完全可行(__test 纯函数 + 已归档日志),三工件全部在边界内;
- H2 仍未测试(实证 invalidate=0 / importState=0)—— 一次实验裁决,失败标准与删除清单已写死;
- **不批准 = 在零证据下放弃一个从未被测试的假设;批准 = 给假设一次可裁决的测试,并预置干净的下车路径。**

**一句话结论:批准进入实现阶段,范围仅限 host 侧三工件(导出器 + Diff + 回顾性验收),六项条件写死;H2 实验单次裁决;失败则按 REMOVE 清单降级,不续第二轮。**
