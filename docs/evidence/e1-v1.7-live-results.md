## Root cause and next protocol

v1.7 projected the authenticated current DSH mutation call into replay exactly once, so durable state did accept the first `change-t1`. However, `foldDshGoalEvents().decision` intentionally preserved the most recent explicit `request_goal_decision` snapshot. Mutation handlers returned that historical snapshot instead of a decision freshly derived from the projected GoalEvent prefix. The model saw `active_attempt=null`, repeated `change-t1`, and the host correctly poisoned the run.

Protocol v1.8 keeps durable replay authoritative and changes only mutation-tool feedback: it returns `decideGoal(contract, replay.events)` after current-call projection. The formal decision tool remains the sole host terminal authority. v1.7 artifacts and score are not migrated or rescored.
