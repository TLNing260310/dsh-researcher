# E1 v1.12 live-stop enforcement — 2026-08-29

## Claim boundary

Protocol v1.12 is an offline-only scorer correction after the preregistered v1.11 replacement ended INVALID. It does not authorize a second replacement or another paid Live E1 run.

Before this correction, that stop was recorded in the protocol and canonical cognition state, but the machine-readable manifest still reported `live_e1=NOT_RUN` and the outer runner had no protocol-authority gate. A caller with the remaining live arguments could therefore reach run-lock verification and cost admission despite the recorded stop.

## Correction

- `manifest.json` and its schema now report `live_e1=STOPPED`.
- manifest validation rejects any other v1.12 live status.
- `run-e1.js` validates the frozen manifest and rejects live mode with `E1_LIVE_STOPPED` before cost acknowledgement, case/run-lock/path parsing, output mutation, DSH startup, or model access.
- offline preflight checks the ordering of this authority gate.
- adversarial repository tests exercise live mode both with and without `--ack-live-cost` and require the same early refusal.

A future restart must deliberately replace the frozen protocol and validator under a new explicit owner-reviewed proof plan. It must use a new candidate, Gate 0, run lock, disjoint evidence root, and complete run; changing a CLI acknowledgement is insufficient.

## Verification

The correction is offline-only. Its verification invokes no DSH process, model, remote API, or network request:

```text
node --test tests/repository-consistency.test.js tests/e1-lock.test.js tests/e1-scorer.test.js
npm run eval:e1:preflight
```

Observed result: targeted tests PASS; preflight reports `live_e1=STOPPED`, `model_calls=0`, and `network_calls=0`.

This proves fail-closed enforcement of the current stop state. It does not prove Live E1 conformance, outcome value, or cross-client portability.
