# v0.8.0-alpha.10 — On-Demand Research Mode, Architecture Lens Library, and an Entry Point That Survives Upgrades

This prerelease adds the feature the project exists for: a model whose attention lands on the changes that matter to a specific project — architecture drift, whether a modification is actually effective, where the project's purpose and likely mistakes are, and whether a change to prompts or context is worth its cost.

It does not reinterpret historical evidence. Every E1 boundary below still applies.

## Included

### `/research` — on-demand, in-session, read-only

`/research <task>` enters read-only research **in the current session** and returns control to the main agent. It does not fire on its own, and it does not require switching modes.

| Command | Behaviour |
|---|---|
| `/research <task>` | Switch this session to read-only, shadow the persona, inject the Route Manifest, and continue as the main agent |
| `/research --session <task>` | Derive a separate certified research session (full Runtime Certificate); the cost is a session switch |
| `/research off` | Exit and restore the pre-entry permission preset and persona |
| `/research status` | Report the effective sandbox, approval policy, and lens library path |

Two layers enforce the read-only contract, because the permission preset alone does not: it constrains the **filesystem**, and a shell write (`pwsh -c "Set-Content ..."`) passes through it. The tool layer therefore refuses `write`, `edit`, shell, terminal, persistent, delegation, workflow, and code-execution tools as well.

In-session mode does not provide `research_doctor` or `research_checkpoint`; those belong to a preset's per-agent installation, which only runs at agent creation. Use `--session` when the certified form is required.

### The architecture lens library

40 lenses across 8 domains, each a six-field record with a collection date. A deterministic router selects by signal scanning plus reciprocal rank fusion. Selection is auditable rather than opaque: the manifest reports `selected`, `skipped`, and `unassessable`, and a gap domain forces an explicit unassessable entry instead of a silent omission.

The tag vocabulary is frozen and checked in CI (`npm run kb:vocab:check`), so a lens cannot drift into an ad-hoc tag.

### The entry point now survives an upgrade

The entry point is registered in the DSH **home patch layer** (`$DSH_HOME/cordis.patch.yml`) rather than inside the shipped presets.

An earlier form appended a row to `minimal`/`standard` under the DSH installation. That location cannot hold it: a DSH upgrade overwrites `node_modules` and silently removes `/research`. The home layer is applied over every profile and lives under the user's home, so the command survives an upgrade with **no repair step**, nothing is written into the deployment, and removal is a marker search over one file the installer owns.

Verified by replacing the entire presets directory with the published package contents and confirming the entry is still composed.

### Corrections to the installer

- **Reverting is byte-exact.** It used to reconstruct the original text and ended with a whitespace normalization that collapsed a run of blank lines inside `cordis`'s own content — a silent one-byte edit to a file the installer does not own. Found by byte-comparing an install against the published package. A revert now prefers the backup, and the fallback is the exact inverse of the append.
- **Two test-isolation holes closed.** `package-smoke` pinned `DSH_HOME` but not the host presets directory, and the lookup fell back to the detected installation when the override named an absent path. The install path was saved by its temporary-plugin-path guard; the revert path had no such guard, so a spawned `uninstall` removed a user's own row and its backup. The override now wins even when absent, which refuses loudly instead of redirecting.
- **One assertion that could not fail was replaced.** The isolation test checked a helper in its own file rather than the installer's output; it passed regardless of what the installer chose.
- **An older in-preset row is migrated away** by both install and uninstall, so an upgrade path does not leave an entry inside the deployment.

- **Outcome value: NOT PROVEN**
- **Multi-client portability: NOT PROVEN**

`/research` itself is proven to work as a mechanism: the command registers, the read-only contract holds fail-closed, and a lens set is selected and reported with its coverage gaps named. **The quality of the lens selection is not measured.** No run has yet shown that the lenses chosen for a real task were the ones that mattered, and the `stack`/`store` tag classes have degenerated into near-open vocabularies that weaken those match signals. Treat selection quality as unproven.

Building and publishing this release does not require a model or remote API call.
