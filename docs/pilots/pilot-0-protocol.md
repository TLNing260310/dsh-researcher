# Pilot 0 protocol — independent workflow evidence

Status: **FROZEN BEFORE RECRUITMENT**  
Window: 21 days after recruitment opens  
Target: 3–5 valid independent results from no more than five accepted participants

## Purpose and boundary

Pilot 0 checks whether an independent user can install the frozen candidate, reach a safe starting state, use Project Research or Goal Governor on a real authorized repository, and submit evidence without exposing private material. It is non-inferential: it does not establish productivity, causal effect, superiority, long-term cognition value, or multi-client portability.

Both positive and negative outcomes count. A blocked, no-value, or too-heavy result is complete when the required evidence is present.

## Independence and admission

A valid participant:

- is not the owner or a maintainer of dsh-researcher;
- has no write permission to this repository and did not design E1, E2, or this pilot;
- discloses compensation or another material relationship;
- uses a real repository they are authorized to inspect, not a fixture or dsh-researcher self-audit;
- receives a Pilot ID before running and uses the frozen tag/commit;
- represents only one counted participant, organization, and repository.

Stars or prior public interest do not invalidate independence. GitHub identity and disclosure are evidence, not cryptographic identity proof.

## Required result

A P2 result contains:

- Pilot ID, exact tag/commit, installation method, DSH/Node/OS/client/model;
- the decision or completion expectation recorded before the run;
- Runtime Certificate, Governor terminal when applicable, and the decision after the run;
- time-to-SAFE, active minutes, and maintainer-help minutes;
- one result class: new fact, invalidated assumption, prevented wrong change, stopped unnecessary work, no change, blocked, or too heavy;
- whether the participant would use the workflow again;
- a locally validated Level-1 `dsh-researcher/feedback/v1` bundle or equivalent structured evidence;
- separate consent choices for anonymous aggregation, Case Library publication, and quotation.

P0 is intake only. P1 is self-report without the required evidence and does not count. P3 adds a public reproducible repository or separately consented redacted case and may enter the Case Library.

## Assistance and invalidity

All maintainer assistance occurs in the public Pilot help desk where possible and is counted in minutes. Setup documentation may be clarified, but the maintainer must not operate the participant's repository, choose their decision, fabricate evidence, or edit their submitted result.

A run is invalid when the version was not frozen, the participant was not admitted first, required evidence is missing, the repository is a fixture/self-audit, independence is undisclosed, or private material cannot be safely removed. Invalid runs remain visible but do not enter the count.

Tasks observed during Pilot 0 cannot be reused as blinded E2 tasks.

## Privacy

GitHub Issues and Discussions are public. Never upload raw sessions, prompts, responses, source code, diffs, absolute paths, remotes, private repository URLs, customer or personal data, environment-variable names, credentials, or secrets. Level 1 is the default. Level 2 claim text requires manual review and separate publication consent. Deleting a GitHub post later is not a confidentiality mechanism.

Authority or sandbox bypasses go through the private security process, not a pilot intake form.

## Success and stop conditions

Pilot 0 completes only when:

- 3–5 P2 results come from distinct participants/organizations/repositories;
- at least two project forms and both product surfaces are represented;
- at least two participants complete without synchronous maintainer help;
- at least three reach SAFE and begin the real task within 15 minutes;
- required evidence is 100% complete;
- at least two results describe a reviewable decision impact, including negative impact if applicable;
- no P0 security/data-loss/authority bypass remains unresolved;
- the same P1 onboarding blocker does not recur for two participants.

If a P0 occurs, recruitment stops. If the same P1 blocker recurs twice, the candidate freezes, the blocker is fixed once, a new candidate is released, and affected runs are rerun. Results are never filtered for being negative.

Amendments after the first accepted result must be appended with a date and rationale; existing thresholds cannot be edited retroactively.
