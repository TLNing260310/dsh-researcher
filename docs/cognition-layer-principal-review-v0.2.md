# Project Cognition Layer Principal Review v0.2

> 角色:Principal Architect(审查者,非作者)。审查对象:`docs/cognition-layer-design-proposal-v0.1.md`。
> 目标:判断该设计是否值得进入实现阶段。对抗性审查 —— 找失败模式,不默认成功。
> 限制(遵守):不写代码 / 不修改 runtime / 不实现 memory / 不扩大范围。
> 方法:六项重点逐项裁决;每项给出"问题 → 证据 → 裁决";最后给 v0.2 必须修改项。

---

## 1. `.cognition/` 与 cognition-state 的边界是否清晰?

**裁决:不清晰。存在"双事实源"风险 —— v0.2 必须先定单一事实源。**

问题链:

1. **v0.1 自相矛盾**:§0 说 `.cognition/` 是"项目内持久认知载体"(事实源口吻),§6.3 又说它是"cognition-state(JSON)的人类可读面"(派生视图口吻)。**同一文档同时宣称两个身份。**
2. **双写冲突**:若两者都是"认知事实",同一信息有两份载体(cognition-state.json + .cognition/core.md)。谁来保证一致?cognition-diff 只对账"状态 vs 代码",**不对账"状态 vs 文档"**。两份载体漂移时,谁权威?未定义。
3. **写路径不对称**:cognition-state 由 research_checkpoint(模型自驱)写入;`.cognition/` 由"任何有写权限的流程"写入。两个写路径、两个 schema、零同步机制。

**必须选择的身份(v0.2 二选一,不可兼得)**:

- **A. `.cognition/` 是派生视图**:cognition-state(JSON)是唯一事实源;`.cognition/` 只是其人类可读渲染,由 host 流程生成,**禁止人工直接编辑**(编辑 = 改状态源或改代码)。→ 简单、可对账,但"人工维护文档"的价值消失。
- **B. `.cognition/` 是权威文档**:人直接维护;cognition-state 是会话内工作副本,落地时**合并进** `.cognition/`(而非独立双份)。→ 保留"人写文档"价值,但需要合并协议(未定义)。

**推荐 A**(与现有工具面一致、零新机制):`.cognition/` = cognition-state 的**渲染视图**,由 `cognition-state-export.js` 家族的一个投影模式生成(不新增 agent tool)。人工只读它,不写它;要改认知,改代码/改会话 → 重导出。**这同时消除了"AI memory 伪装"的一半问题(见 §2)。**

---

## 2. 是否存在把 AI memory 伪装成工程文档的问题?

**裁决:存在,而且是本设计最大的定位风险 —— v0.2 必须诚实命名。**

问题链:

1. **内容来源**:六类信息(Mission/原则/不变量/决策/状态/风险)全部可由 Researcher(模型)产出。若 `.cognition/` 的内容**主要由模型生成**,它就是 AI 的跨会话记忆 —— 只是扩展名从 `.json` 换成了 `.md`。
2. **读者**:v0.1 声称"人机共读"。但**人真的会读吗?** 工程实践中,人会读 README(用法)、读 ADR(决策)、读 CLAUDE.md(工具配置);`.cognition/` 的六类信息里,只有 decisions 是"人传统上读的"。core/constraints/state/drift 是 **agent 消费为主**。
3. **伪装成本**:如果 80% 读者是 agent,这就是 memory 系统 —— 而本任务明确"不实现 memory 系统"。**把 memory 叫成"工程文档"不改变它的本质,只改变它的审查待遇。**
4. **风险后果**:若按"文档"设计(人工维护、无自动回灌),而实际是 memory 用途 → 维护责任悬空(§3)、检测无载体(§4);若按"memory"设计 → 违反任务限制。

**必须的诚实命名(v0.2)**:声明 `.cognition/` 的**读者优先级**:

- **若读者是 agent 优先** → 承认它是"文档化 memory",设计必须含:自动生成(模型投影)、版本对齐(与状态同源)、失效驱动更新(非人工)。此时**价值主张 = memory 的人类可读面**,与"工程文档"无关。
- **若读者是人优先** → 承认它是"工程文档",设计必须含:人工编辑为第一写入路径、评审流程、内容须人可辩护。此时**价值主张 = 结构化 ADR+**,与 cognition-state 松耦合。

**v0.1 的"既是又不是"是最大缺陷。v0.2 必须选边。** 本审查倾向:**agent 优先(诚实面)+ 人可读渲染(附加面)** —— 因为六类信息中四类是 agent 工作记忆,硬说成"人的文档"是自欺。

## 3. 维护责任是否明确?

**裁决:不明确 —— "任何有写权限的流程" = 没有负责人。**

问题链:

1. v0.1 §0:"任何有写权限的流程(人、CI、授权的 agent)都能维护" —— **"都能"≠"有人会"**。多所有者 = 无所有者。
2. 三个候选维护者全部悬空:
   - **人**:无更新义务(README/CLAUDE.md 的普遍命运:没人主动维护);
   - **CI**:无钩子设计(v0.1 未定义任何 CI 触发);
   - **授权的 agent**:无写入工具(禁止新增 agent tool;现有 Researcher 零写契约,写不了)。
3. **R4"自动更新 state.md"是空头支票**:没有任何执行者被授权执行它 —— agent 没有写工具,CI 没有钩子,人没有义务。
4. **维护义务与修改流程脱钩**:v0.1 说"修改命中 R1–R3/R5 时更新" —— 但**谁检测命中?谁触发更新?** 未定义。

**v0.2 必须指定的维护契约(三选一,不能全选)**:

- **方案 1(推荐,与工具面一致)**:`.cognition/` 由 host 投影流程**每次 Researcher 会话后自动重建**;人工与 agent 都**只读**。维护 = 重导出,责任在流程,不在人。→ 与 §1 身份 A 配套。
- **方案 2**:指定**单一维护角色**(如"文档守护者")+ PR 强制检查(修改 do-not-touch 区必须附 `.cognition/` 更新,CI 验证)。→ 与身份 B 配套,但需要 CI 改动(超出"只研究文档协议"范围,需批准)。
- **方案 3**:降级为"可选人工文档",不承诺维护 —— **等于承认它不会比 CLAUDE.md 好**。

**推荐方案 1**:维护责任 = 自动投影流程,唯一事实源 = cognition-state。人零维护负担,agent 零写权限 —— 与所有现有限制兼容。

## 4. 相比 README / CLAUDE.md / AGENTS.md / ADR,真正新增价值是什么?

**裁决:真实增量只有两个,且都依赖 cognition-state 已有工具;其余是包装。**

| v0.1 声称的增量 | 真实? | 分析 |
|---|---|---|
| 信息密度/token 效率(分类+预算) | ⚠️ 部分 | CLAUDE.md 也能分层(多文件+索引);"3900 token 预算"是纪律不是能力。**弱增量** |
| 条目级生命周期(active/superseded/expired) | ⚠️ 部分 | ADR 已有状态机(superseded)。`.cognition/` 只是换格式。**弱增量** |
| 被推翻条件字段 | ✅ 真实 | CLAUDE.md/ADR 都没有"什么条件会让这条失效"的显式声明。**这是新东西** |
| R1–R5 漂移检测 | ✅ 真实(但有条件) | 检测规则的**机械真值来自 cognition-diff**(已有工具);`.cognition/` 只是输出面。**增量在 diff,不在文档格式** |
| 人机共读 | ❌ 非增量 | README/ADR 本来就是人读的;CLAUDE.md 本来就是 agent 读的。"共读"是**折中不是优势** —— 往往是双方都读不顺 |

**净判断**:

- **真正新增价值 = "被推翻条件" + "证据锚失效检测(R5)"** —— 两者合起来是:**认知条目可以条件化失效,而不是等人工发现过期**。这是 CLAUDE.md/ADR 完全没有的。
- **但**:这两个增量**不依赖 `.cognition/` 格式** —— 它们依赖 cognition-diff 与条目 schema。`.cognition/` 目录本身只是展示容器。
- **结论**:如果 v0.2 把格式简化为"cognition-state 的一种 markdown 渲染"(身份 A + 方案 1),增量成立且零新机制;**如果坚持"独立人工维护文档"(身份 B),增量消失,退化为 CLAUDE.md 换皮** —— 那时不如直接用 CLAUDE.md。

## 5. 设计失败模式 —— 一年后失败,最可能原因是什么?

**预测(按概率排序)**:

1. **维护悬空(35%)**:没有负责人 → 文档 6 个月内过期 → agent 不信任 → 不读 → 死亡螺旋。**这与 CLAUDE.md 的普遍命运完全一致 —— 说明 v0.1 没有解决"为什么这个会不一样"。**
2. **检测规则无执行载体(25%)**:R1–R5 定义了"询问开发者"和"自动更新",但**没有任何机制触发检测** —— 没有 CI 钩子、没有 agent 工具、没有 pre-commit。规则停留在纸面 → 一年后无人记得它们存在。
3. **双事实源冲突(15%)**:cognition-state.json 与 `.cognition/` 各自演化 → 认知不一致 → 修复成本高 → 放弃一方(大概率放弃 `.cognition/`)。
4. **定位暴露(15%)**:被社区/用户识破"这是 AI memory 叫成文档" → 信任损失;或被问到"和 CLAUDE.md 有什么区别"时答不出增量 → 项目被搁置。
5. **H2 实验失败拖累(10%)**:cognition-state 本身(实验 C+)若显示无增量,`.cognition/` 作为其渲染面失去存在理由。

**一句话失败叙事**:`v0.1 最大的失败风险不是技术,而是它没有回答'谁维护、谁触发检测、它是文档还是 memory' —— 三个问题不答,一年后它就是一个没人更新的 markdown 目录,和 CLAUDE.md 一样,只是名字更好听。`

## 6. v0.2 必须修改项(六项,缺一不可)

| # | 修改项 | 内容 | 对应问题 |
|---|---|---|---|
| **M1. 单一事实源声明** | 明确:cognition-state(JSON)= 唯一事实源;`.cognition/` = 派生渲染视图,**人工与 agent 只读,不直接编辑**。删除"任何有写权限的流程都能维护"。 | §1 双事实源 |
| **M2. 诚实命名** | 声明读者优先级:**agent 优先(memory 的人类可读面)**,人可读为附加面。删除"人机共读"的模糊主张,删除"它不是 memory 系统"的否认句(改为:"它是 cognition-state 的文档化渲染,memory 由状态机承担,文档不新增记忆")。 | §2 伪装问题 |
| **M3. 维护责任 = 自动投影** | `.cognition/` 由 host 投影流程(复用 cognition-state-export 家族)在 Researcher 会话后自动重建;**零人工维护义务、零 agent 写权限**。删除 R4"自动更新 state.md"的空头承诺(改为:渲染流程总是最新,不存在"更新"动作)。 | §3 维护悬空 |
| **M4. 检测载体 = cognition-diff 输出面** | R1–R5 全部**降级为认知条目的标注**:"被推翻条件"进入条目 schema;"证据锚失效"由 cognition-diff 标记;**"询问开发者"改为"渲染视图中的醒目标记 + 人工决策"**(不新增 agent 工具,不新增交互机制)。删除"CI 钩子/自动更新/询问流程"等无载体承诺。 | §4 无执行载体 |
| **M5. 增量最小化声明** | 明确唯一增量 = "被推翻条件 + 证据锚失效检测";删除"信息密度/预算/共读"等弱增量主张(它们不构成与 CLAUDE.md 的差异)。若增量不被接受,直接使用 CLAUDE.md 多文件方案。 | §4 弱增量包装 |
| **M6. 失败前提声明** | 声明:`.cognition/` 的价值**依赖 cognition-state 的价值(H2 实验)**;H2 失败 → `.cognition/` 一并降级。禁止在 H2 未决时把 `.cognition/` 当作已证明的价值。 | §5 拖累风险 |

**v0.2 后的形态(一句话)**:`.cognition/` = cognition-state 的 markdown 渲染视图;由现有 export 工具投影生成;唯一事实源是状态机;检测(cognition-diff)自动标注失效;人只读;增量只剩"条件化失效"一项;价值与 H2 绑定。

## 最终判断:是否值得进入实现阶段?

**裁决:有条件否决 v0.1 原样实现;批准"v0.2 修订后"进入实现。**

理由:

1. **v0.1 的三个致命歧义(边界/伪装/维护)不解决,实现即失败** —— 按原样实现会产出一个"像 CLAUDE.md 的目录 + 没人触发的检测规则",一年后必然腐化(§5 概率 60%+)。
2. **但核心增量真实存在**:被推翻条件 + 证据锚失效检测,是 CLAUDE.md/ADR 没有的;且**实现成本极低**(渲染视图 + 条目 schema 标注,复用现有工具,零新机制)。
3. **v0.2 六项修改全部是"删承诺/定身份",不是"加功能"** —— 完全符合"不写代码/不扩范围"限制;修订本身是文档工作,可立即做。
4. **不实现的代价**:认知层(H2)即使验证成功,也缺一个人可读的落地形态;而 v0.1 原样实现的风险远大于收益。

**批准条件**:v0.2 完成 M1–M6 修订 → 重新审查 → 通过后仅实现"渲染投影"(host 侧,复用 export 工具,零新 agent tool)→ 与 Experiment C+ 并行验证(不阻塞 H2)。
